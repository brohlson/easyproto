# SQLite project pilot

Import a committed folder project into a new `.easyproto` file. The folder remains a usable recovery copy. Import copies the published document and its command receipts, together with the project name, page layout, ordered boards, token source and compiled CSS, and project-relative assets. Earlier folder snapshots stay with the original project. The import should be run while the folder has no writer because its name and assets are independent of the document pointer.

The file has its own SQLite application ID and container version. The document schema version and IDs retain their existing meaning. Keep separate ordered records for boards, receipts and assets, and store identical source strings once by SHA-256. Assets retain the ordered paths and bytes that determine capture identity. Electron uses the existing Project command service to validate data, resolve retries, reject stale edits and drive the preview.

On import, stage a private database in the destination directory, write it in one transaction, check it, close it, and publish it under a new name without overwriting any file. A process interruption before publication leaves the destination absent. An interruption after publication leaves a complete file. If interruption leaves the same file linked to a staging name, copy the completed file to a new name before opening it for edits. A folder or database with the same project ID still gets a fresh activation.

SQLite opens existing project files with rollback journaling and full synchronization. Each edit checks the stored revision and commits changes and its command receipt in one transaction. The UI and MCP respond after commit. There is one local writer. Closing a process may leave a rollback journal that SQLite uses to recover. Keep the database and any journal together through recovery, and close the app before copying its active file. Power-loss recovery and remote filesystems require separate qualification.

The reader opens clean files read-only and allows recovery of an ordinary, single-link rollback journal. It rejects WAL, shared-memory and multi-database recovery sidecars. It also checks record counts and stored byte lengths before loading payloads, then verifies the source hashes. Edits and renames require the same filesystem file selected at open. If another program replaces it, reopen the selected file before editing. Editing writes enforce the same file and metadata capacities as the reader before committing.

Folder creation remains the desktop default during the pilot. A finished file can be opened via `--project=PATH` or **Open project** on macOS. Browser publication still takes a committed snapshot.
