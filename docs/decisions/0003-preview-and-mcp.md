# Isolate local previews and bind MCP to the open project

The trusted renderer loads bundled files at `easy-proto://ui`. The main process validates IPC by window, main frame and exact URL. The preload exposes scene reads/subscriptions and validated position and viewport size updates. Electron disables Node integration, enables context isolation and sandboxing, denies permissions, and denies popups and downloads. The authenticated MCP tools and UI layout changes share the same document command service.

Mockups render as empty-sandbox iframes at `easy-art://preview`, with an opaque document origin. A restrictive response policy also sandboxes directly loaded documents. The application parses a preview copy of the source and strips executable and embedding elements, metadata, browser hints and event handlers. Both consumers eagerly load images from the same preview markup. Hyperlinks are inert in arrange previews. Canonical source stays intact on disk. Supported styling is inline CSS plus the board CSS resource. Images and webfonts use the assigned preview's asset namespace. Data images are allowed, while arbitrary scripts, nested embeds, remote networking, filesystem URLs and navigation outside registered preview documents are blocked. Project assets are resolved from an in-memory allowlist acquired on open, with symlink, hard link and size checks at load time. Preview markup deeper than 128 parsed elements is discarded before serialization. Canvas previews are for arrangement and visual review. The iframe is pointer-transparent.

Capture pins the authorized snapshot, source bytes, viewport and asset map when the tool starts. A dedicated hidden window without a preload loads the same artboard response directly under its response-level sandbox. This avoids relying on a hidden cross-process iframe to composite before capture. A fixed readiness probe runs through Chromium DevTools in an isolated world without universal access. It waits for the frame, fonts, image decoding and paint with bounded deadlines. The resulting PNG is normalized to the CSS viewport dimensions on Retina and returns project/source revision, source and asset digests, Chromium version, capture dimensions, device pixel ratio, observed media preferences and unresolved dependencies. The readiness scan checks HTML images and computed URL images in common CSS properties for elements and their standard pseudo-elements. A requested revision that is stale at dispatch is rejected. Error codes distinguish rendering, readiness and screenshot failure. The capture queue is limited to four jobs.

MCP uses the official TypeScript SDK v1 and stateless Streamable HTTP on `127.0.0.1`. It requires a bearer token, an exact local Host header and no Origin header before consuming bounded JSON. Tokens are process configuration and stay outside project files. Project authority is bound to the folder instance currently selected by the desktop. See [project selection](0004-project-selection.md) for the activation and switch contract. There is no internal HTTP bridge. See [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security), the [MCP v1 server documentation](https://ts.sdk.modelcontextprotocol.io/server) and the [Codex MCP configuration](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

External agents can create pages, rename them, move artboards between them, and commit up to six new artboards in one document command. A contact-sheet request validates all artboard IDs and captures them in order from the same committed revision using the isolated renderer. The contact sheet is assembled from pixels in main. The server rechecks the project activation, revision, and request cancellation before, between, and after rendering. A stale, canceled, or invalid request returns no partial image.

Artboard activity belongs to the current project activation. The authenticated `set_artboard_activity` tool uses an artboard ID and caller-provided activity UUID to start, renew, or end a two-minute lease. The activation can hold at most 128 leases, and the artboard stays busy while it has any lease or pending MCP update or capture. The desktop receives only a boolean per board on the existing scene subscription. An independent scene version orders those updates alongside document commits. The label and animation run in trusted canvas chrome outside the preview frame. Activity stays in memory and ends when the activation is retired.

Committed tokens add one exact `tokens.css` resource per preview URL. The main process serves the generated stylesheet before artboard CSS through the existing preview origin and content policy. Token imports use a trusted file picker and validate in main on save. Exports use a trusted save picker for committed bytes. The narrow clipboard command looks up a committed variable by name. None of these operations is available to mockup frames. MCP token reads and replacements require the current project ID and activation. Capture identifies the pinned token document and CSS by digest.


The Arbitrary size option enables a bottom-right canvas control for that artboard in the current view. The handle and labels stay at a fixed screen size. During a drag, transient dimensions update the iframe viewport. Releasing publishes the integer width and height through the same revision-checked document command used by device presets, taking one undo step. The gesture captures the starting document revision, so a concurrent edit causes rejection and restores the latest committed geometry. Changing only geometry preserves the preview URL and iframe identity. Saved dimensions persist independently of the temporary resize-control visibility. Canvas zoom transforms the board's display without changing its HTML viewport.
