# Isolate local previews and bind MCP to the open project

The trusted renderer loads bundled files at `easy-proto://ui`. The main process validates IPC by window, main frame and exact URL. The preload exposes scene reads/subscriptions and validated position updates. Electron disables Node integration, enables context isolation and sandboxing, denies permissions, and denies popups and downloads. The authenticated MCP tools and UI position changes share the same document command service.

Mockups render as empty-sandbox iframes at `easy-art://preview`, with an opaque document origin. A restrictive response policy also sandboxes directly loaded documents. The application parses a preview copy of the source and strips executable and embedding elements, metadata, browser hints and event handlers. Canonical source stays intact on disk. Supported styling is inline CSS plus the board CSS resource. Images and webfonts use the assigned preview's asset namespace. Data images are allowed, while arbitrary scripts, nested embeds, remote networking, filesystem URLs and navigation outside registered preview documents are blocked. Project assets are resolved from an in-memory allowlist acquired on open, with symlink and size checks at load time. Canvas previews are for arrangement and visual review. The iframe is pointer-transparent.

Capture pins the authorized snapshot, source bytes, viewport and asset map when the tool starts. A dedicated hidden window without a preload wraps the same kind of sandboxed iframe. A fixed readiness probe runs through Chromium DevTools in an isolated world without universal access. It waits for the frame, fonts, image decoding and paint with bounded deadlines. The resulting PNG is normalized to the CSS viewport dimensions on Retina and returns project/source revision, source and asset digests, Chromium version, capture dimensions and observed unresolved dependencies. A requested revision that is stale at dispatch is rejected. Error codes distinguish rendering, readiness and screenshot failure. The capture queue is limited to four jobs.

MCP uses the official TypeScript SDK v1 and stateless Streamable HTTP on `127.0.0.1`. It requires a bearer token, an exact local Host header and no Origin header before consuming bounded JSON. Tokens are process configuration and stay outside project files. Project authority is bound to the concrete instance opened for the lifetime of the app. There is no internal HTTP bridge. See [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security), the [MCP v1 server documentation](https://ts.sdk.modelcontextprotocol.io/server) and the [Codex MCP configuration](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
